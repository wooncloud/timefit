# Timefit 백엔드 Docker 환경 이슈 리포트

> 작성일: 2026-02-21

---

## 1. dev.sh 스크립트 불일치 문제

### 현상

`npm run dev` 실행 시 프론트엔드는 정상 동작하지만, 백엔드 서버가 정상적으로 실행되지 않음.

### 원인

`scripts/dev.sh`에서 `start` 명령어만 `docker-compose.prod.yml`을 사용하고, 나머지 명령어(`stop`, `restart`, `status`, `clean`, `rebuild`)는 기본 `docker-compose.yml`을 참조하고 있었음.

| 명령어 | 수정 전 | 수정 후 |
|--------|---------|---------|
| `start` | `docker-compose -f docker-compose.prod.yml --env-file .env.prod up -d --build` | 동일 (정상) |
| `restart` | `docker-compose restart timefit-back` | `$COMPOSE_CMD restart timefit-backend` |
| `stop` | `docker-compose down` | `$COMPOSE_CMD down` |
| `status` | `docker-compose ps` | `$COMPOSE_CMD ps` |
| `clean` | `docker-compose down -v` | `$COMPOSE_CMD down -v` |
| `rebuild` | `docker-compose --profile dev build --no-cache` | `$COMPOSE_CMD build --no-cache` |

### 해결

- 상단에 `COMPOSE_CMD` 변수로 공통 명령어 추출: `docker-compose -f docker-compose.prod.yml --env-file .env.prod`
- 모든 명령어에서 해당 변수를 일관되게 사용하도록 수정
- 컨테이너명 `timefit-back` → `timefit-backend`로 통일 (prod compose의 실제 서비스명에 맞춤)
- `rebuild`에서 존재하지 않는 `--profile dev` 옵션 제거

## 2. PostgreSQL 초기화 실패

### 현상

PostgreSQL 컨테이너가 아래 에러를 반복하며 crash-loop에 빠짐:

```
initdb: error: directory "/var/lib/postgresql/data" exists but is not empty
initdb: hint: If you want to create a new database system, either remove or empty
the directory "/var/lib/postgresql/data" or run initdb with an argument other than
"/var/lib/postgresql/data".
```

### 원인

이전에 `docker-compose.yml`(`postgres:latest`)로 생성된 `postgres_data` 볼륨 데이터가 남아있는 상태에서, `docker-compose.prod.yml`(`postgres:16-alpine`)로 새로 실행하면서 PostgreSQL 버전이 달라져 `initdb`가 기존 데이터 디렉토리를 초기화하지 못함.

### 해결

기존 볼륨을 삭제하고 다시 시작:

```bash
# 방법 1: 직접 명령어
cd timefit-back
docker-compose -f docker-compose.prod.yml down -v
./scripts/dev.sh start

# 방법 2: dev.sh 활용
./scripts/dev.sh clean && ./scripts/dev.sh start
```

> **주의:** 볼륨을 삭제하면 DB 데이터가 모두 삭제됩니다. 기존 데이터를 보존해야 한다면 `pg_dump`로 백업 후 진행하세요.

## 3. Nginx 시작 실패

### 현상

Nginx 컨테이너가 시작 직후 아래 에러로 종료되며 crash-loop에 빠짐:

```
nginx: [emerg] cannot load certificate "/etc/nginx/ssl/fullchain.pem":
BIO_new_file() failed (SSL: error:80000002:system library::No such file or directory:
calling fopen(/etc/nginx/ssl/fullchain.pem, r)
error:10000080:BIO routines::no such file)
```

### 원인

1. **`init-certs.sh` 실행 권한 없음 (치명적):** `init-certs.sh`가 자체 서명 인증서를 생성해야 하지만, 실행 권한이 없어 건너뛰어짐. 로그에 `Ignoring /docker-entrypoint.d/00-init-certs.sh, not executable`로 확인 가능.
2. **http2 directive deprecated (경고):** Nginx 최신 버전에서 `listen 443 ssl http2;` 문법이 deprecated됨. 동작에는 영향 없으나 경고 발생.

```
nginx: [warn] the "listen ... http2" directive is deprecated,
use the "http2" directive instead in /etc/nginx/conf.d/default.conf:36
```

### 해결

`init-certs.sh`에 실행 권한 부여 후 컨테이너 재시작:

```bash
chmod +x timefit-back/init-certs.sh
```

이후 nginx 컨테이너를 재시작하면 `init-certs.sh`가 정상 실행되어 인증서를 생성하고 nginx가 정상 기동됨.
